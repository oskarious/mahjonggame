# Engine (packages/engine) and bots

Read when touching rules, scoring, game state, views, analysis or bots, or writing engine tests.
Hidden information and bot fairness: [fair-play.md](fair-play.md).

## Layout

```
packages/engine/        @mahjong/engine: pure TS, no I/O. Rules, scoring, game state, views, analysis, bots
  src/tiles.ts          tile ids/kinds, notation parser ("123m406p11z"; 0 = red five), dora
  src/rules.ts          RuleSet, EMA_2025 and DEFAULT_RULES presets; TENHOU (log replays only, not offered for play)
  src/hand.ts           decomposition, waits, shanten (memoized per-suit)
  src/scoring.ts        yaku, fu (with fuParts breakdown), limits, payments
  src/game.ts           state machine: createGame / applyAction / legalActions / pendingSeats
  src/view.ts           viewFor (per-seat redacted view + hint levels), redactEvent
  src/analysis.ts       tenpai / tiles-away / waits / per-discard options; goodWaitAcceptance (1-shanten draws that
                        reach a wait of 5+ copies; Learn only so far, no bot uses it)
  src/bot.ts            skill-based bots, botProfile(skill), botElo / skillForElo
  src/scenario.ts       scenario(): a playing position from tile notation (hands, melds, discards, draws, dora, riichi);
                        used by engine/game-server tests and the Learn exercises
  src/hidden.ts         scrambleHidden: the definition of hidden information (fairness tests, see fair-play.md)
  src/rng.ts            wall RNG: ChaCha20 keyed with SHA-256(seed), pure TS
  src/bot-ratings.ts    GENERATED by scripts/calibrate.ts — do not hand-edit
  src/fixed-wall.ts     withWall(): deal a hand from an explicit wall. Test-only, NOT exported from the index (online
                        and offline games always deal from the seeded RNG)
  scripts/calibrate.ts  bot-vs-bot Elo calibration (worker threads)
  scripts/tenhou-replay.ts  opt-in bulk replay of downloaded Tenhou logs (see below)
  test/                 vitest; helpers.ts has score() and play() for scripted games (+ re-exports scenario)
```

## Principles

- **Pure and deterministic.** `applyAction(state, action)` returns `{ state, events }` on a structuredClone; no I/O,
  no timers, no randomness except the seeded wall RNG in the state. A game is fully reproducible from
  `(rules, seed, actions[])` — that log is the plan for replays, crash recovery and storage.
- **Server-authoritative by design.** Clients only get `viewFor(state, seat)` and `redactEvent(e, seat)`. Never leak
  other hands, the wall, or who has call options (call windows wait for everyone; seats without options are skipped).
- **Rules are data.** Behaviour differences go into `RuleSet` flags. Presets: `EMA_2025` (strict) and `DEFAULT_RULES`
  (online default = EMA + east-only by default, red fives, bankruptcy, all abortive draws, riichi needs 1000 pts).
- **Engine TS constraints:** no enums/parameter properties (erasableSyntaxOnly, Node type stripping), import with
  `.ts` extensions, `structuredClone` is declared in `src/globals.d.ts` so the engine needs neither DOM nor Node types.
  Packages that typecheck engine sources transitively (protocol) must include `packages/engine/src/globals.d.ts` in
  their tsconfig, or `structuredClone` is unknown; the game server gets it from `@types/node` instead.
- Tenpai is decided by `waits()` (EMA: waiting only on a tile you hold all four of is noten, melded copies included;
  Tenhou counts only concealed copies at an exhaustive draw: `deadWaitCopies`), not by shanten alone.
- Changing wall generation or action shapes breaks replay of stored games and offline saves (see fair-play.md and
  web.md → offline autosave).

## Testing conventions

- Scoring tests use `score(hand, opts)` from `test/helpers.ts`; the concealed string lists the winning tile last.
  The helper rejects hands that are not exactly 14 tiles (quads count 3) — it has caught several miscounted tests.
- Game scenarios use `scenario({ hands, melds, discards, draws, riichi, turn, wallSize, ... })` (engine export) +
  `play(state, steps)`.
  `play` auto-passes open call windows; pass `{ settle: false }` to inspect a window. Default dora indicator is 3z
  (dora = north) — avoid 4z in hands unless you want dora.
- Bots use randomness: pass a seeded `random` in tests (`seedRng` + `randomInt`), or games become non-reproducible.
- Where EMA differs from common (Tenhou/WRC) practice, tests pin EMA and also exercise the RuleSet flag.

## Tenhou log replays (correctness oracle)

Real games from Tenhou's Houou table are replayed through the engine with the `TENHOU` preset and every result must
match Tenhou's: draws, legality of every call/discard/riichi/kan, yaku, han, fu, dora/red/ura, limits, points, score
changes, tenpai at draws, abortive draws, nagashi mangan, who starts the next hand with what counters and scores,
when the game ends (all-last dealer stop, West-round sudden death, bankruptcy) and final points/uma.

- `test/tenhou/mjlog.ts` parses mjlog XML (tile ids are ours: 0-135, red fives = copy 0); `test/tenhou/replay.ts`
  builds each hand's `WallLayout` from the log (starting hands, live draws, replacement draws, dora/ura indicators;
  unseen tiles filled), deals it with `withWall`, converts the log to engine actions (passes for seats with call
  options; identical tile copies in chii/pon are mapped to the engine's) and reports differences. Each hand starts
  from Tenhou's scores, so one difference doesn't cascade.
- `test/tenhou.test.ts` runs the committed fixtures (`test/tenhou/fixtures/`, names and shuffle data stripped),
  chosen for edge cases; a test asserts that they still cover them (quads, chankan, rinshan, double ron, abortive
  draws, nagashi, kazoe, yakuman, pao, West round, bankruptcy).
- Bulk (opt-in, not in `npm test`): download logs (ids from https://tenhou.net/sc/raw/ `scc*.html.gz`, files from
  `https://tenhou.net/0/log/?<id>`; be polite, ~1 request/s) into a directory and run
  `npm run tenhou-replay --workspace @mahjong/engine -- <dir>`. Last run (Oct 2026): 4,082 Houou games / 41,558
  hands, no differences (~1.5 min on worker threads, 16 cores).
- Limit: logs only show what players did, so the oracle catches an engine that is too strict (forbids a legal call,
  scores differently), never one that is too permissive (missing furiten, riichi with too few tiles left): unit tests
  cover those.
- Tenhou flags (all off / `immediate` in EMA and DEFAULT): `openKanDora: 'afterDiscard'` (open/added quad dora on
  the quad player's next discard or quad; a rinshan win doesn't count it), `nagashiMangan`, `depositsToFirstRonWinner`
  (with `honbaToAllRonWinners: false`), `dealerStopsAllLast` (win/tenpai, not abortive draws), `suddenDeath`,
  `deadWaitCopies: 'concealed'`.

## Bots

- `botAction(g, seat, { skill | profile, random })`. `botProfile(skill 0..1)` interpolates knobs: blunder rate,
  softmax noise, ukeire, value awareness, defense (genbutsu / suji / walls), push-fold, open-hand reading, call style,
  riichi style (dama with value), kans, placement awareness.
- Elo per skill is **measured**, not guessed: `scripts/calibrate.ts` plays East-only games and fits Bradley-Terry.
  Last run: ~958 (skill 0) → ~1309 (skill 1); **skill 0.15 is pinned to 1000**, a new player's starting rating (a
  guess until humans have played; re-anchoring is a constant shift). 0.9 and 1.0 plateau — raising the ceiling needs
  better play (look-ahead, reading), not more knobs.
- **Re-run calibration after any bot change** and commit the regenerated `bot-ratings.ts`:

  ```bash
  npm run calibrate --workspace @mahjong/engine -- --games 15000 --write   # ~8 min, all cores
  ```

- Bot *players* (named, rated accounts on the game server) are in [game-server.md](game-server.md).
